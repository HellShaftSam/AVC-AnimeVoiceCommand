# RECOMMENDATIONS_DATA_MODEL — нормализованная модель данных

Код: `src/lib/recs/types.ts`, `src/lib/recs/profile.ts`. Принцип: **каждое поле опционально, если источник его не гарантирует; ничего не выдумываем**.

## 1. Элемент профиля — `RecProfileEntry`

Реальное действие пользователя с тайтлом.

| Поле | Тип | Источник | Комментарий |
|---|---|---|---|
| `animeId` | number | сайт/локальный трекинг | стабильный внутренний ID (числовой ID сайта) |
| `slug` | string | сайт | человекочитаемый алиас; дедупликация дублей |
| `title` | string | сайт | каноническое название |
| `status` | `watching\|planned\|completed\|dropped\|favorite\|on_hold` | `listId` сайта (0..5) | статус ТОЛЬКО из списка; фав — отдельно |
| `ownRating` | `number \| null` (1..10) | `user.rating` | **личная** оценка; 0/нет → `null` (никогда не 0!) |
| `siteRating` | `number \| null` | `rating.average` | рейтинг сайта; отдельно от личной |
| `isFavorite` | boolean | `user.list.is_fav` | бонус силы, не подменяет статус |
| `source` | `'site' \| 'local-progress'` | — | сайт приоритетен; локальный трекинг — только если тайтла нет на сайте |
| `episode` | `number \| null` | локальный трекинг | сила сигнала локального просмотра |

Дубликаты между списками: статус по приоритету `favorite > dropped > watching > completed > on_hold > planned` (`STATUS_PRECEDENCE`), оценка/фав склеиваются. Детерминировано, покрыто тестами.

## 2. Якорь вкуса — `RecAnchor`

Профиль = производное от действий, НЕ ручной список.

| Поле | Смысл |
|---|---|
| `entry` | `RecProfileEntry` |
| `strength` | сила сигнала 0..1 (таблица ниже) |
| `negative` | true → жёсткое исключение тайтла + слабый негативный вектор |
| `genres` / `studios` | метаданные, дозаполняются после обогащения (`applyAnchorMetadata`) |

Таблица сил (ТЗ §6.3; константы в `types.ts` — документированы и настраиваемы):

| Сигнал | Сила |
|---|---|
| Высокая личная оценка | `ratingStrength(rating, threshold)`: 10 → 1.0, 7 → 0.65, 5 → 0.15 |
| Избранное | 0.7 (список id=4) / бонус +0.35 поверх другого списка |
| Смотрю | 0.5 (умеренный позитив; НЕ «любит») |
| В Планах | 0.35 (слабо-умеренный) |
| Просмотрено без оценки | 0.3 (слабый; отсутствие оценки ≠ 0) |
| Отложено | 0.2 |
| Брошено | 0 — жёсткое исключение тайтла + негативный якорь 0.8 |
| Личная оценка < порога | 0 — жёсткое исключение тайтла + негативный якорь (сила = `(threshold − rating)/(threshold − 1)`) |
| Локальный просмотр | 0.5 («смотрю») — слабее не бывает по определению сигнала |

`positiveEvidence` = сумма позитивных сил. `< 1.0` → холодный старт (честная общая подборка).

## 3. Профиль — `RecProfile`

| Поле | Смысл |
|---|---|
| `accountKey` | числовой userId сайта или `null` (гость → режим `logged-out`, никакой персонализации) |
| `anchors` | якоря вкуса |
| `genreWeights` / `negativeGenreWeights` | Map<жанр, вес>; позитив и негатив РАЗДЕЛЬНЫЕ; негативный вклад ×0.6 — жанр целиком не отвергается (ТЗ §6.1) |
| `studioWeights` | Map<студия, вес> (позитивные, ×0.5) |
| `knownIds` / `knownSlugs` | всё известное (любой список/фав/локальный трекинг) — для исключения и дедупликации |
| `hardExcludedIds` | брошено/ниже порога — вето ДО ранжирования, сильнее настройки `excludeKnown` |
| `franchiseParents` | позитивные тайтлы-родители (силой > 0) — сиквелы брошенных не рекламируются |

## 4. Кандидат — `RecCandidate`

`AnimeCard` + `genres[]`, `studios[]`, `malId?`, `origin: 'franchise' | 'catalog' | 'anilist'`, `franchiseParent?` (id/название/связь). Все поля метаданных опциональны: отсутствие — НЕ негатив (компоненты честно дают 0 / знаменатель уменьшается).

## 5. Хранение/приватность (ТЗ §11)

| Что | Где | Зачем |
|---|---|---|
| Библиотека (60 с) | память сервера | не дёргать сайт повторно |
| Метаданные тайтлов (1 ч) | память сервера | батчи дешевле |
| AniList-ответы (6 ч) | память сервера | уважение к внешнему API |
| Снапшот результата | SQLite `AppSetting` `recs:snapshot:{accountKey}` | мгновенное открытие + честный stale при недоступном сайте |
| Обратная связь | SQLite `RecFeedback` (accountKey, animeId, action, title) | «Не интересно»/«Уже видел» + отзыв |
| Профиль | НЕ хранится — воспроизводим из исходных данных (фингерпринт) | сайт остаётся источником истины |

Снапшот/фидбек ключуются accountKey: смена аккаунта/логаут → снапшоты удаляются (`invalidateRecsSnapshots`), утечки между аккаунтами нет. Cookie/пароли/токены в рекомендательных записях не хранятся.
