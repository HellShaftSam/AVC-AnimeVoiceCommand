## Что сделано в Task 23 (коротко)

1. **Расследование на живом сайте** (не по догадкам):
   - `/api/anime/{id}` → `episodes{count,aired}` + `viewing_order` (структура!);
   - `/api/anime/{id}/videos` → ОДНА матрица (8710 записей у Ван-Писа), поле
     `number` — СТРОКА («1168.5», «119+120»), пагинации НЕТ;
   - JS сайта (`react.min.js`): плеер показывает серии выбранной озвучки, чипы
     озвучек считают уникальные МЕТКИ; инфоблок — «Серий: {count}»;
   - **грязные данные сайта**: Шиппуден `aired=58` при матрице 1..500 — сайт при
     этом сам показывает «Episodes: 500».
2. **Корни багов**:
   - «Наруто ~57–58 серий» — приложение брало `episodes.aired` (58 — грязное
     поле Шиппудена) как максимум сетки; правильный источник — видео-матрица;
   - «Ван-Пис 1180 vs 1157» — приложение рисувало плоскую сетку 1..1180 по всем
     озвучкам (aired=1180), а сайт показывает покрытие выбранной озвучки
     (Субтитры = 1157); плюс parseInt ломал «1168.5» и «119+120».
3. **Реализация**: новый `src/lib/sites/yummy/episodes.ts` (чистые стадии:
   label → index → stats → validation → watch order → report), типы в
   `src/lib/avc/types.ts` (`EPISODE_PARSER_VERSION=3`), адаптер/executor/UI
   переведены на каноническую модель, кэш с TTL+версией, «Порядок просмотра»
   (UI + переходы), диагностика (`/api/site/debug/{id}`, секция в debug-панели,
   экспорт JSON), голос «серия N» поддерживает >999 (`\d{1,4}`).
4. **Проверено**: selftest 51/51 (`scripts/episode-parser-selftest.ts`),
   lint 0, tsc (src) 0, E2E в браузере: Наруто 220, Шиппуден 531 кнопки +
   предупреждение, Ван-Пис 1181 → «Субтитры» 1157, переход по «Порядку
   просмотра» открывает тайтл, «серия 1180» честно переключает озвучку.
