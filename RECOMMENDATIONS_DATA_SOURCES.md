# RECOMMENDATIONS_DATA_SOURCES — верифицированные источники данных

Каждая строка проверена по коду/живым запросам (октябрь 2026). Ничего не выдумывается: недоступное помечено и обрабатывается деградацией.

## 1. Библиотека аккаунта (сервер-авторитетно)

| Параметр | Значение |
|---|---|
| Источник | `GET https://old.yummyani.me/api/users/{numericId}/lists/{listId}` |
| Аутентификация | cookie-сессия сайта (X-Application заголовок из бандла сайта); без куки → 401 |
| numericId | только число; берётся из `GET /api/profile` (парсинг защитный) |
| Пагинация | нет — сайт отдаёт список целиком |
| Свежесть | кэш 60 с в `/api/recs` + обход по `refresh=1` |
| Сервер-авторитетен | да — это данные аккаунта на сайте |
| Статус | **РАБОТАЕТ** (используется библиотекой приложения с v1.0.x) |

Списки: 0 Смотрю · 1 В Планах · 2 Просмотрено · 3 Брошено · 4 Любимые · 5 Отложено.

## 2. Своя оценка пользователя

| Параметр | Значение |
|---|---|
| Источник | `user.rating` в элементе списка (1..10); `0` = оценки нет → нормализуется в `null` |
| Шкала | **десятибалльная** (подтверждено бандлом сайта: `PUT /rate {rate: 1..10}`) → конверсия не требуется, порог 5/10 применяется напрямую |
| Отдельность | хранится/используется ТОЛЬКО как личная оценка; рейтинг сайта (`rating.average`) никогда не подменяет её |
| Статус | **РАБОТАЕТ** |

## 3. Избранное

| Параметр | Значение |
|---|---|
| Источник | `user.list.is_fav` в элементах списков (дублируется списком id=4 «Любимые») |
| Особенность | флаг лежит ПОВЕРХ основного списка → статус берётся из `listId`, фав даёт бонус силы сигнала |
| Статус | **РАБОТАЕТ** |

## 4. Прогресс просмотра

| Параметр | Значение |
|---|---|
| Сайт | ❌ наружу не отдаёт (пишет `PUT /video/{id}` внутри своей сессии) |
| Приложение | ✅ локальный трекинг `WatchProgressEntry` (SQLite, accountKey = числовой userId сайта или `anon`) |
| Вес сигнала | слабый: «открыл серию» ≠ «нравится» (0.5, как «Смотрю», и только если тайтла нет на сайте) |
| Статус | **ЧАСТИЧНО** (локально) — ограничение задокументировано |

## 5. Метаданные тайтлов (жанры/студии/франшиза/рейтинг сайта)

| Параметр | Значение |
|---|---|
| Источник | `GET /api/anime/{id}`: genres[], studios[], rating.average, viewing_order[], remote_ids.myanimelist_id |
| Получение | батчи с потолком конкурентности (якоря ×4, кандидаты ×5) + кэш 1 ч; карточки каталога жанров не содержат — обогащаются деталями |
| Статус | **РАБОТАЕТ** (адаптер кэширует 5 мин; demo-фолбэк отфильтровывается) |

## 6. AniList (опционально, по умолчанию ВЫКЛЮЧЕНО)

| Параметр | Значение |
|---|---|
| Роль | только ДОПОЛНИТЕЛЬНЫЙ генератор кандидатов; не замена библиотеке YummyAnime |
| Сопоставление | ТОЛЬКО через MAL ID (`remote_ids` сайта → `Media(idMal_in)` GraphQL); ID YummyAnime ≠ ID AniList и никогда не смешиваются |
| Обратный маппинг | название AniList → `GET /api/search?q=` на YummyAnime → ТОЛЬКО точное совпадение названия → кандидат; не нашлось на сайте → не показывается |
| Лимиты | 1 батч-запрос на ≤50 MAL ID, кэш 6 ч, таймаут 12 с; недоступен → `[]`, движок работает без него |
| Аккаунт | не требуется |
| Статус | **РЕАЛИЗОВАН, выключен по умолчанию** (переключатель в настройках вкладки) |

## 7. Сессия/аккаунт-идентичность

| Параметр | Значение |
|---|---|
| Кто сейчас | `loadWebSession()` → `fetchProfile()` → числовой userId |
| Нет сессии | режим `logged-out` — никакой персонализации, честное сообщение + кнопка входа |
| Логаут | `POST /api/yummy/logout` инвалидирует ВСЕ снапшоты рекомендаций + кэш AniList (сценарий J) |
| Изоляция | снапшот хранится под ключом `recs:snapshot:{accountKey}` — чужой аккаунт не увидит чужих подборок |

## 8. Cookie/пароли

- Cookie сессии живут только в серверном хранилище; в ответах `/api/recs*`, логах и UI их нет (проверено: ответ содержит только `mode/items/profileSummary/...`).
- Пароль используется одним запросом к сайту и не сохраняется (существующее поведение приложения, не тронуто).
